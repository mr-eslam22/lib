# نظام أتمتة وإدارة طباعة الكتب المدرسية — Windows Print Automation System

نظام مكتبي احترافي متكامل مخصص لبيئات المطابع والمكتبات المدرسية، لإدارة دورة طباعة الكتب والملازم الدراسية بالكامل على بيئة Windows والربط مع ماكينات الطباعة الإنتاجية (HP وKyocera).

## 1. نظرة عامة وفلسفة النظام

في المطابع والمكتبات الحقيقية، قد تستغرق طباعة 20 نسخة من كتاب مدرسي مكون من 200 صفحة عدة ساعات، وخلال هذا الوقت قد يحدث:
- انحشار ورق (Paper Jam).
- نفاد الورق في الدرج (Out of Paper).
- انقطاع مفاجئ في التيار الكهربائي أو إعادة تشغيل للكمبيوتر.
- توقف مؤقت لخدمة Windows Print Spooler.

**المبدأ الأساسي للنظام:**
> **لا يُعتبر الكتاب قد طُبع بمجرد إرسال البيانات من Windows Spooler!**
> يفرق النظام بدقة بين قبول المهمة في الطابور، ومعالجتها، والإبلاغ عن انتهاء الضخ، وبين **التأكيد الفيزيائي الفعلي** الذي يجريه المشغّل بعد فحص ومراجعة الملازم المطبوعة.

## 2. المعمارية وطبقات المشروع

تم بناء المشروع بتقنية **C# و.NET 8** مع **WPF** لواجهة سطح مكتب حديثة تدعم الاتجاه العربي بالكامل (RTL)، ومقسم إلى 9 طبقات مستقلة:

│   │   └── Services/
│   │       ├── LibraryService.cs             # فحص المجلدات المتداخلة، استخراج الميتاداتا، عد صفحات PDF، منع التكرار
│   │       ├── CustomerService.cs            # إدارة العملاء والأكواد والبحث

├── installer/

## 3. نظام التحقق الفيزيائي متعدد المستويات

يمر كل أمر طباعة بالحالات التالية:

| الحالة | المعنى | التأكيد |
|---|---|---|
| `Accepted` | تم قبول أمر الطباعة في طابور Windows Spooler | إلكتروني |
| `Processing` | جاري تحويل وضخ البيانات إلى منفذ الطابعة | إلكتروني |
| `DeviceReportedComplete` | أفادت خدمة Spooler أو الماكينة بانتهاء استقبال البيانات | إلكتروني غير كافٍ |
| `NeedsVerification` | انتظر ضخ الملف، ولكن لم يتم بعد تأكيد خروج الورق سليمًا | بانتظار المشغّل |
| `PhysicallyVerified` | **أكد المشغّل بعد العد والفحص الميداني خروج النسخ سليمة** | تأكيد بشري معتمد |
| `NeedsAttention` / `RecoveryRequired` | حدث خطأ أو انقطاع أو توقف غير طبيعي يتطلب مراجعة فورية | حالة استعادة |

## 4. الاستكمال الآمن بعد التعطل وانقطاع الكهرباء

### 1. الكشف التلقائي عند بدء التشغيل
عند إغلاق التطبيق فجأة أو انقطاع الكهرباء وإعادة فتحه، يقوم `RecoveryService.CheckAndFlagIncompleteJobsOnStartupAsync` بفحص جميع المهام التي كانت في حالة (`Printing`، `Submitted`، `Spooling`).
يتم تحويلها فورًا إلى `RecoveryRequired` مع منع إعادة إرسالها تلقائيًا للماكينة حتى لا تتكرر طباعة كتب تم إخراجها بالفعل.

### 2. معادلة النسخ الآمنة (Safe Copy Math)
إذا كان المطلوب 20 نسخة، وخرجت 7 نسخ سليمة وانحشرت الورقة في النسخة الثامنة:
- يدخل المشغّل في شاشة الاستعادة: **النسخ السليمة = 7**، **النسخ التالفة = 1**.
- يحسب النظام تلقائيًا: **النسخ المتبقية = 20 - 7 = 13 نسخة**.
- يُسجل القرار وملاحظات الموظف في سجل التدقيق `PrintJobEvents`.
- عند الضغط على «إنشاء مهمة استكمال للمتبقي»، يتم توليد مهمة فرعية جديدة برقم `JOB-xxxx-R` بعدد 13 نسخة فقط ومربوطة بالمهمة الأصلية.

### 3. استئناف الطباعة على الوجهين (Duplex)
إذا توقفت الماكينة عند صفحة محددة داخل كتاب:
- إذا كانت الطباعة على وجهين والصفحة الأخيرة المكتملة فردية (وجه الورقة فقط طُبع)، فإن النظام يعيد بدء الاستكمال من نفس الصفحة الفردية لضمان عدم اختلال تقابل الصفحات (Front/Back Alignment).

## 5. استيراد وفهرسة مجلدات الكتب بالكامل

يدعم النظام استيراد مجلد يحتوي على مئات المجلدات والملفات الفرعية بضغطة زر واحدة:

```
Books/
  الصف الأول الثانوي/
    اللغة العربية/
      كتاب الطالب.pdf
      كتاب التدريبات.pdf
    اللغة الإنجليزية/
      Student Book.pdf
      Workbook.pdf
  الصف الثاني الثانوي/
    اللغة العربية/
      كتاب الطالب.pdf
```

### المميزات:
- استخراج الصف الدراسي والمادة واسم الكتاب تلقائيًا من مسار المجلد واسم الملف.
- فحص سلامة ملف الـ PDF وحساب عدد صفحاته بدقة دون الاعتماد على برامج خارجية.
- حساب بصمة المحتوى (SHA-256) لمنع تكرار الكتب حتى في حال تغيير مسارها.
- حفظ المسارات فقط والميتاداتا في قاعدة بيانات SQLite المحلية دون حشو محتوى الملفات الثقيل في القاعدة.
- دعم أسماء الملفات العربية والمسارات الطويلة والتعامل الآمن مع الملفات المقفلة أو التالفة.

## 6. الربط مع ماكينات HP وKyocera

### 1. ماكينات Kyocera (TASKalfa وECOSYS)
- يوصى باستخدام تعريف **Kyocera KX Driver** أو **KPDL (PostScript)**.
- يدعم النظام قراءة حالة أدراج الورق (درج 1، درج 2، درج جانبي) وضبط مقاسات A4 وB5 والوجهين (Duplex) تلقائيًا.
- يوفر النظام طبقة `KyoceraHpSnmpAdapter` للاستعلام المباشر عبر بروتوكول SNMP عن حالة الورق ومستوى التونر في الماكينات الشبكية.

### 2. ماكينات HP LaserJet (Enterprise وMFP)
- يوصى باستخدام **HP Universal Print Driver (UPD)**.
- تم تفعيل عزل الماكينات (Machine Isolation): إذا حدث انحشار ورق (Paper Jam) أو نفاد للورق في ماكينة HP، يقوم النظام بإيقاف طابور تلك الماكينة فقط، بينما تستمر ماكينة Kyocera في تنفيذ مهامها دون أي توقف!

## 7. البناء الآلي عبر GitHub Actions وإنتاج ملف التثبيت

تم إعداد ملف سير العمل داخل:
`.github/workflows/build-windows.yml`

### خطوات الـ Workflow:
1. يعمل تلقائيًا عند أي `push` أو `pull_request`، أو تشغيل يدوي `workflow_dispatch`.
2. يتم تشغيله على بيئة `windows-latest`.
3. تثبيت .NET 8 SDK واستعادة الاعتماديات.
4. تشغيل حزمة الاختبارات الآلية وحفظ تقرير الاختبارات `test_results.trx`.
5. بناء تطبيق Windows x64 بصيغة Self-Contained (لا يحتاج تثبيت .NET مسبقًا على جهاز العميل).
6. تجميع ملف التثبيت الاحترافي `WindowsPrintAutomation-Setup.exe` باستخدام Inno Setup المدمج في بيئة GitHub Actions.
7. إنتاج حزمة محمولة مضغوطة `WindowsPrintAutomation-Portable-win-x64.zip`.
8. رفع الملفات كـ **Artifacts** لتنزيلها مباشرة من صفحة الـ Workflow Run.
9. عند إنشاء Tag يبدأ بـ `v*` (مثل `v1.0.0`)، يتم إنشاء **GitHub Release** تلقائيًا وإرفاق ملف التثبيت به.

## 8. التثبيت والتشغيل في بيئة الإنتاج

1. توجه إلى تبويب **Actions** في مستودع GitHub.
2. اختر أحدث تشغيل ناجح للـ Workflow: `Build & Test Windows Desktop App`.
3. قم بتنزيل ملف الـ Artifact باسم `WindowsPrintAutomation-Release-win-x64`.
4. فك الضغط وشغل `WindowsPrintAutomation-Setup.exe` للتثبيت، أو شغل `WindowsPrintAutomation.UI.exe` مباشرة من الحزمة المحمولة.
5. يبدأ التطبيق تلقائيًا بالاتصال بقاعدة بيانات SQLite المحلية وتفعيل نمط `WAL`.

## 9. الاختبارات الآلية

يحتوي مجلد `tests/WindowsPrintAutomation.Tests/` على اختبارات تغطي:
- استيراد المجلدات المتداخلة وتصنيف الكتب العربية.
- منع تكرار الكتب عبر بصمة SHA-256.
- إنشاء طلبات متعددة الكتب وحساب عدد الأوراق بدقة للوجه الواحد والوجهين.
- كشف الملفات التالفة أو غير الموجودة قبل إرسال أمر الطباعة.
- تحويل المهام المعلقة إلى `RecoveryRequired` فور إعادة تشغيل التطبيق.
- حساب النسخ المتبقية والتأكيد الفيزيائي للمشغّل.
- عزل الماكينات التي تواجه انحشار ورق واستمرار باقي الماكينات في العمل.
- سلامة نسخ SQLite الاحتياطية واستعادتها.
